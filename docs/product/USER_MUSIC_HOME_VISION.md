# User Music Home Vision

작성일: `2026-05-04`

이 문서는 `my-forever-music`을 사용하는 회원이 왜 이 사이트에 가입하고, 무엇을 반복적으로 하게 되는지 정의합니다. 구현 우선순위는 이 문서를 기준으로 `PROJECT_KEY_SERVICE.md`와 함께 판단합니다.

## 1. 핵심 관점

대부분의 회원은 이미 하나의 음악 스트리밍 플랫폼을 구독하고 있습니다.

사용자는 이 서비스를 통해 구독 중인 플랫폼과 연동하고, 그곳의 플레이리스트를 가져온 뒤, 더 정확한 음악 추천과 장기적인 취향 보존을 얻고자 합니다.

따라서 `my-forever-music`은 단순 추천 페이지가 아니라 `사용자 소유의 음악 취향 홈`이어야 합니다.

## 2. 사용자 가치

- 내 구독 플랫폼의 플레이리스트를 쉽게 가져온다.
- 플랫폼을 옮겨 다녀도 내가 모은 플레이리스트와 음악 취향을 잃지 않는다.
- 내 취향에 맞는 음악을 더 정확하고 쉽게 추천받는다.
- 추천 결과를 평가하면서 점점 더 나에게 맞는 추천 모델을 만든다.
- 사이트 안에서 나만의 플레이리스트를 만들고 음악을 감상한다.

## 3. 제품 원칙

### 3-1. 플랫폼은 출처이고, PMS는 사용자 소유 공간이다

Spotify, TIDAL, YouTube Music, Apple Music 같은 플랫폼은 원본 playlist와 playback target을 제공하는 출처입니다.

현재 구현 우선순위는 `Spotify -> TIDAL -> YouTube Music`이며, Apple Music은 개발자 계정 준비 전까지 보류합니다.

하지만 사용자의 장기 음악 정체성은 특정 플랫폼 계정에 묶이지 않고, `PMS (Personal Music Space)`에 보존되어야 합니다.

### 3-2. 가져온 플레이리스트는 정식 사용자 라이브러리로 승격된다

플랫폼에서 가져온 데이터는 임시 import 결과로 끝나면 안 됩니다.

가져온 playlist와 track은 canonical user library로 동기화되어야 하며, 이후 추천, 평가, 재생, 사용자 제작 playlist의 기반 데이터가 됩니다.

### 3-3. 추천은 평가와 행동으로 계속 좋아져야 한다

추천 결과는 단순히 보여주는 데서 끝나지 않습니다.

사용자가 좋아요, 싫어요, 저장, 건너뛰기, 재생 완료, playlist 추가 같은 행동을 남기면, 그 데이터는 다시 PMS와 사용자 모델에 반영되어야 합니다.

### 3-4. 사이트는 음악 감상 체류 공간이어야 한다

사용자는 추천만 받고 떠나는 것이 아니라, 로그인 후 이 사이트 안에서 탐색하고, 평가하고, 자기 playlist를 만들고, 음악을 감상하게 됩니다.

따라서 공통 플레이어, 현재 재생 큐, playlist 편집, 추천 결과 저장은 핵심 경험입니다.

## 4. 대표 사용자 흐름

1. 사용자가 회원가입 또는 로그인한다.
2. 구독 중인 스트리밍 플랫폼을 연결한다.
3. 연결된 플랫폼에서 playlist를 가져온다.
4. 가져온 track마다 Spotify 오디오 특성 전체 스냅샷을 채운다. 실패 시 가짜 값을 만들지 않고 import를 중단하거나 명시적인 재시도/제외 정책으로 처리한다.
5. 가져온 playlist와 track을 PMS user library에 저장한다.
6. PMS user library와 Spotify 오디오 특성 스냅샷을 기반으로 사용자별 음악 학습 모델을 만든다.
7. 사용자는 자신의 취향 기반 추천을 받는다.
8. 추천 결과를 평가하거나 새 playlist에 추가한다.
9. 사이트 안에서 음악을 재생하고 감상한다.
10. 사용자가 플랫폼을 바꾸더라도 PMS user library와 취향 모델은 계속 유지된다.

## 5. 도메인 설계에 주는 의미

- `auth`: 사용자의 장기 계정과 온보딩 상태를 관리한다.
- `platform`: 외부 스트리밍 플랫폼 연결, OAuth, credential, playlist provider를 관리한다.
- `pms`: 사용자 소유 playlist, track, audio feature snapshot, 평가, 행동 데이터를 보존한다.
- `ems`: 외부 공개 playlist와 트렌딩 음악을 탐색하고 후보군을 만든다.
- `gms`: PMS 사용자 모델을 통과한 추천 후보를 보여주고 평가를 받는다.
- `player`: 웹과 데스크탑에서 같은 음악 감상 상태를 유지한다.

## 6. MacBook 시험 서비스 구현 우선순위

1. 회원가입, 로그인, 세션 복원
2. Spotify OAuth와 playlist import 안정화
3. PMS user library 영속 저장과 playlist별 bootstrap 안정화
4. TIDAL provider 확장
5. YouTube Music provider 확장
6. 사용자별 음악 학습 모델 개발
7. 추천 결과 평가 저장
8. 사용자 제작 playlist 생성과 track 추가
9. 공통 플레이어와 재생 큐 고도화
10. Last.fm scrobble과 사이트 내부 행동 이벤트를 사용자 모델에 반영
11. Apple Music provider 확장
12. Ubuntu 서버 이전

## 7. 구현 해석 원칙

- 새 기능을 만들 때는 먼저 `사용자의 장기 음악 취향 보존`에 도움이 되는지 확인합니다.
- 외부 플랫폼 기능은 특정 플랫폼 종속 기능으로 끝내지 말고, 가능한 한 PMS canonical model로 흡수합니다.
- 사용자별 음악 학습 모델은 플랫폼 연동과 PMS user library 저장이 안정화된 뒤 개발합니다.
- 모델의 1차 입력은 가져온 playlist, track metadata, Spotify audio feature snapshot, Last.fm scrobble, 사이트 내부 행동 이벤트입니다.
- 추천 기능은 결과 표시보다 `평가 -> 학습 -> 재추천` 루프까지 닫는 것을 목표로 합니다.
- 재생 기능은 부가 기능이 아니라 사용자가 사이트에 머무는 핵심 이유로 봅니다.
