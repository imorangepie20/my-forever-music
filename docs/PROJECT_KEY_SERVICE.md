# 핵심 서비스 정의

이 문서는 `my-forever-music`이 최종적으로 어떤 서비스를 제공해야 하는지 정의하는 제품 기준 문서입니다.

- 이 문서는 `목표 상태`를 설명합니다.
- 현재 구현 상태와 다를 수 있습니다.
- 아키텍처, API, 데이터 모델을 설계할 때 이 문서를 제품 기준으로 참고합니다.

## 1. 서비스 한 줄 정의

`my-forever-music`은 사용자가 구독 중인 음악 스트리밍 플랫폼의 플레이리스트를 가져와 자기 소유의 음악 취향 라이브러리로 보존하고, 플랫폼을 옮겨도 유지되는 개인화 추천과 음악 감상 경험을 제공하는 서비스입니다.

상세한 사용자 가치와 체류 경험 기준은 [product/USER_MUSIC_HOME_VISION.md](/Users/woosungjo/music-space/my-forever-music/docs/product/USER_MUSIC_HOME_VISION.md) 를 함께 봅니다.

## 1-1. 사용자가 이 서비스를 쓰는 이유

- 구독 중인 스트리밍 플랫폼의 플레이리스트를 쉽게 가져오기 위해
- 플랫폼을 바꾸더라도 내가 모은 플레이리스트와 음악 취향을 잃지 않기 위해
- 내 취향에 맞는 음악을 더 정확하고 쉽게 추천받기 위해
- 추천 결과를 평가하고, 나만의 플레이리스트를 만들기 위해
- 웹사이트 안에 머물면서 음악을 감상하기 위해

이 서비스에서 외부 스트리밍 플랫폼은 원본 데이터와 재생 target을 제공하는 `출처`이고, 사용자의 장기 음악 취향과 playlist는 `PMS`에 보존되는 것이 원칙입니다.

## 2. 핵심 도메인

### PMS

`PMS (Personal Music Space)`는 사용자의 원본 음악 취향 데이터가 쌓이는 개인 공간입니다.

- 사용자의 스트리밍 플랫폼 플레이리스트를 저장합니다.
- 플랫폼에서 가져온 playlist와 track을 정식 사용자 라이브러리로 승격합니다.
- 사용자가 선택한 seed track, artist, genre를 저장합니다.
- 사용자가 직접 만든 playlist와 추천 결과에서 저장한 track을 관리합니다.
- 사용자의 평가와 행동 데이터를 학습 재료로 축적합니다.
- 플랫폼 변경 이후에도 유지되는 사용자 소유 음악 취향의 기준점입니다.
- 개인화 모델의 가장 중요한 입력 데이터 공간입니다.

### EMS

`EMS (External Music Space)`는 외부 음악 탐색 공간입니다.

- 각 스트리밍 플랫폼의 공개 플레이리스트를 수집합니다.
- 트렌딩 플레이리스트와 트렌딩 트랙을 수집합니다.
- 수집한 트랙의 오디오 특성 데이터를 생성하거나 보강합니다.
- 사용자가 외부 음악을 탐색하고 PMS로 가져오는 진입점 역할을 합니다.

### GMS

`GMS (Gateway Music Space)`는 사용자 모델을 통과한 추천 결과가 모이는 공간입니다.

- EMS에서 수집된 트랙 중 사용자 취향에 맞는 후보를 보여줍니다.
- 사용자 평가를 받습니다.
- 추천 결과를 사용자의 playlist에 저장하거나 재생 큐에 추가하는 흐름을 제공합니다.
- 평가 결과를 다시 PMS로 환류시켜 모델 개선에 사용합니다.

## 3. 음악 분석 데이터 기준

음악 분석의 기본 기준은 우선 `Spotify`가 제공하는 오디오 특성 데이터입니다.

### 3-1. 오디오 특성

- `Danceability`: 리듬, 템포, 비트 안정성을 기반으로 춤추기 적합한 정도
- `Energy`: 빠르고 강렬하며 시끄러운 정도
- `Valence`: 음악의 긍정성 또는 감정 밝기
- `Acousticness`: 어쿠스틱 악기 비중
- `Liveness`: 라이브 공연 녹음일 가능성
- `Speechiness`: 말소리, 랩, 대화 비중
- `Tempo`: BPM 기준의 템포

### 3-2. 사용자 행동 데이터

사용자의 실제 청취 행동도 분석에 포함합니다.

- `재생 횟수 및 시간`: 얼마나 자주, 얼마나 오래 듣는지
- `건너뛰기 비율`: 끝까지 듣지 않고 넘기는지
- `저장 및 플레이리스트 추가`: 선호 곡으로 저장하거나 직접 플레이리스트에 추가하는지
- `청취 시간대`: 어떤 시간대에 어떤 장르나 분위기를 듣는지

### 3-3. 추가 추천 신호

- `인기도 점수`: 스트리밍 수와 최신성을 반영한 점수
- `아티스트 연관성`: 사용자가 선호하는 아티스트와의 유사도
- `장르 연관성`: 사용자가 선호하는 장르와의 유사도
- `지역성 데이터`: 특정 지역에서의 인기 흐름

## 4. 데이터 확보 원칙

### 4-1. 우선 기준

- 플레이리스트에 담긴 각 트랙은 가능한 한 `Spotify` 오디오 특성 기준으로 분석합니다.
- 동일 곡이 다른 플랫폼에 있어도 분석 기준은 먼저 Spotify 특성에 맞춥니다.

### 4-2. 실제 데이터 원칙

- Spotify에서 오디오 특성을 직접 가져오지 못하는 곡이 있을 수 있습니다.
- 사용자 플로우에서는 이 곡을 가짜 오디오 특성으로 채우지 않습니다.
- 대신 import를 중단하거나, 이후 명시적인 재시도/부분 제외 정책을 만들어 사용자가 알 수 있게 처리합니다.

## 5. 서비스 핵심 흐름

### 5-1. 사용자 온보딩

플랫폼 연결 구현 순서는 `Spotify -> TIDAL -> YouTube Music`입니다. Apple Music은 Apple Developer 계정 준비 전까지 보류합니다.

1. 회원가입 시 사용자가 구독 중인 스트리밍 서비스를 선택합니다.
2. 해당 스트리밍 서비스의 API를 통해 사용자의 플레이리스트를 가져옵니다.
3. 가져온 플레이리스트는 import snapshot으로 저장한 뒤 정식 `PMS user library`로 동기화합니다.
4. 이후 플랫폼을 바꾸더라도 `PMS user library`와 사용자 취향 모델은 유지됩니다.

### 5-2. PMS 분석

1. 플레이리스트의 각 트랙 오디오 특성을 확보합니다.
2. 사용자의 구독 플랫폼에서 플레이리스트를 가져올 때는 구성 트랙마다 `Spotify 오디오 특성 전체 스냅샷`을 채운 뒤 저장합니다.
3. Spotify 직접 매칭이나 오디오 특성 조회가 실패하면 임의 값을 저장하지 않고 import를 중단합니다.
4. 확보한 특성 데이터를 기반으로 플레이리스트와 사용자 취향을 분석합니다.
5. 이 분석 결과는 seed, mood, 선호도, 추천 모델 입력값으로 이어집니다.

### 5-3. 개인화 모델 생성

개인화 모델은 플랫폼 연동과 PMS user library 저장이 먼저 안정화된 뒤 개발합니다.

1. 사용자가 구독 플랫폼을 연결하고 playlist를 가져옵니다.
2. 가져온 playlist와 track을 정식 `PMS user library`로 저장합니다.
3. 각 track에 Spotify 오디오 특성 전체 스냅샷을 채웁니다.
4. 약 `10만 곡` 수준의 Spotify 오디오 특성을 가진 기반 트랙 데이터를 준비합니다.
5. 이 기반 데이터로 먼저 공통 추천 모델을 학습합니다.
6. 여기에 사용자의 PMS playlist 기반 track을 추가 학습시켜 사용자 고유 모델을 만듭니다.
7. 사용자의 PMS에 새 playlist가 추가되면 모델을 다시 보강합니다.
8. 사용자 평가, 재생, 스킵, 저장, playlist 추가 같은 행동 데이터도 반영해 모델을 지속적으로 개선합니다.

### 5-4. EMS 수집과 GMS 추천

1. `EMS`는 각 스트리밍 플랫폼의 공개 플레이리스트와 트렌딩 플레이리스트를 지속적으로 수집합니다.
2. 수집한 EMS 트랙에도 오디오 특성 데이터를 생성하거나 보강합니다.
3. EMS 트랙은 사용자 모델로 평가됩니다.
4. 평가 결과 사용자의 취향에 맞는 트랙은 `GMS`에 추가됩니다.

### 5-5. 사용자 피드백 환류

1. 사용자는 GMS에 들어온 트랙을 평가합니다.
2. 사용자는 추천 트랙을 저장하거나 자기 playlist에 추가합니다.
3. 사용자는 사이트 안에서 음악을 재생하고, 재생 완료/스킵/반복 같은 행동 데이터를 남깁니다.
4. 이 평가와 행동 결과는 다시 PMS 학습 데이터로 반영됩니다.
5. 이 루프를 통해 사용자 모델은 점점 더 개인화됩니다.

## 6. 사용자 경험 요구사항

### 6-1. EMS 페이지

EMS 페이지에서는 아래 경험을 제공해야 합니다.

- 플랫폼별 다양한 공개 플레이리스트 표시
- 트렌딩 곡과 트렌딩 플레이리스트 표시
- 사용자가 원하는 플레이리스트를 선택하거나 생성할 수 있는 흐름
- 선택한 플레이리스트를 PMS로 가져와 분석과 학습에 반영하는 흐름

### 6-2. 공통 음악 플레이어

- 어느 페이지에서든 음악을 재생할 수 있어야 합니다.
- 페이지를 이동해도 플레이어 상태가 유지되어야 합니다.
- 웹앱과 향후 데스크탑 앱에서도 일관된 재생 경험을 제공해야 합니다.
- 추천 결과, PMS playlist, 사용자 제작 playlist가 모두 같은 플레이어와 재생 큐를 사용해야 합니다.

### 6-3. 사용자 제작 플레이리스트

- 사용자는 PMS 안에서 자기 playlist를 만들 수 있어야 합니다.
- 추천 결과나 외부 탐색 결과를 자기 playlist에 저장할 수 있어야 합니다.
- 사용자 제작 playlist는 특정 스트리밍 플랫폼 계정에만 묶이지 않아야 합니다.
- 가능한 경우 연결된 플랫폼의 track playback target을 함께 보관합니다.

## 7. 운영 요구사항

- EMS 데이터는 주기적으로 계속 업데이트되어야 합니다.
- 사용자 모델은 PMS 추가 데이터와 행동 데이터에 따라 재학습되어야 합니다.
- 플랫폼 원본 데이터, 보강 오디오 특성 데이터, 사용자 행동 데이터는 분리된 책임으로 관리하는 것이 바람직합니다.
